# 🏥 HelpDesk Медин - Полное описание модулей

## 📋 Обзор системы

**HelpDesk Медин** - это комплексная система управления технической поддержкой для медицинской организации. Система включает 6 основных модулей, объединенных единой архитектурой и системой прав доступа (RBAC).

---

## 🎯 Модули системы

### 1. 📚 База знаний (Knowledge Base)
**URL**: `/knowledge`, `/knowledge/:id`  
**Иконка**: BookOpen  
**Назначение**: Централизованное хранилище инструкций и решений типовых проблем

#### Основные функции:
- ✅ Пошаговые инструкции с изображениями
- ✅ Категоризация по типам (Оборудование, ПО, Сеть, Принтеры, Общее)
- ✅ Поиск по содержимому
- ✅ Статистика просмотров
- ✅ Процент успешности решения
- ✅ Теги для быстрого поиска
- ✅ Создание заявки прямо из инструкции

#### Структура данных:
```typescript
interface KnowledgeGuide {
  id: string;
  title: string;
  category: 'hardware' | 'software' | 'network' | 'printer' | 'common';
  description: string;
  tags: string[];
  steps: GuideStep[];
  successRate: number;  // Процент успешных решений
  views: number;
  createdAt: string;
  updatedAt: string;
  author: User;
}
```

#### Примеры инструкций:
- "Принтер не печатает"
- "Компьютер не включается"
- "Нет доступа к 1С"
- "Замена картриджа HP LaserJet"

#### Категории:
- **Оборудование** (hardware): Компьютеры, мониторы, периферия
- **ПО** (software): 1С, МИС, офисные программы
- **Сеть** (network): Интернет, VPN, принтеры
- **Принтеры** (printer): Все проблемы с печатью
- **Общее** (common): Базовые инструкции, FAQ

### 2. 🎫 Заявки (Tickets)
**URL**: `/tickets`, `/tickets/:id`, `/tickets/create`, `/tickets/:id/edit`  
**Иконка**: Home  
**Назначение**: Система учета и обработки заявок на техническую поддержку

#### Основные функции:
- ✅ Создание заявок пользователями
- ✅ Назначение исполнителя (техник/администратор)
- ✅ Управление статусами (Новая, В работе, Ожидание, Решена, Отменена)
- ✅ Приоритеты (Низкий, Средний, Высокий, Критический)
- ✅ Категории проблем
- ✅ Комментарии и история изменений
- ✅ Фильтрация по статусу, приоритету, категории
- ✅ Поиск по номеру, названию, описанию
- ✅ Редактирование заявок (с правами)
- ✅ Удаление заявок (с правами)

#### Структура данных:
```typescript
interface Ticket {
  id: string;
  number: string;           // #1001, #1002...
  title: string;
  description: string;
  category: TicketCategory; // hardware, software, network, printer, other
  priority: TicketPriority; // low, medium, high, critical
  status: TicketStatus;     // new, in_progress, waiting, resolved, cancelled
  createdAt: string;
  updatedAt: string;
  author: User;             // Кто создал
  assignee?: User;          // Кому назначено
  comments: Comment[];      // История обсуждения
}
```

#### Статусы заявок:
- **Новая** (new): Только что созданная заявка
- **В работе** (in_progress): Техник работает над проблемой
- **Ожидание** (waiting): Ожидание запчастей или действий пользователя
- **Решена** (resolved): Проблема устранена
- **Отменена** (cancelled): Заявка отменена

#### Приоритеты:
- **Низкий** (low): Не срочно, плановая работа
- **Средний** (medium): Стандартные проблемы
- **Высокий** (high): Влияет на работу отдела
- **Критический** (critical): Блокирует работу, требует немедленного реагирования

#### Категории:
- **Оборудование** (hardware): Компьютеры, мониторы, периферия
- **ПО** (software): Программы, лицензии, обновления
- **Сеть** (network): Интернет, локальная сеть, VPN
- **Принтер** (printer): Печать, сканирование
- **Другое** (other): Прочие вопросы

#### Workflow заявки:
```
1. Пользователь создает заявку → Статус "Новая"
2. Админ/Техник назначает исполнителя → Статус "В работе"
3. Техник работает, добавляет комментарии
4. При необходимости → Статус "Ожидание" (запчасти, согласование)
5. Проблема решена → Статус "Решена"
```

### 3. 📄 Документы (Documents)

**Назначение**: Управление технической документацией и актами

#### Основные функции:

- ✅ Прикрепление файлов (PDF, Word)
- ✅ Фильтрация по типу и статусу
- ✅ Поиск по содержимому

#### Структура данных:
```typescript
interface Document {
  id: string;
  number: string;             // DOC-1234567890
  title: string;
  type: DocumentType;         // act, repair, maintenance, inventory, other
  status: DocumentStatus;     // draft, active, archived
```

- **Черновик** (draft): Документ в процессе создания

#### Примеры использования:

### 4. 📦 Склад (Inventory)
**URL**: `/inventory`, `/inventory/create`  
**Иконка**: Package  
**Назначение**: Учет запчастей, расходников и оборудования

#### Основные функции:
- ✅ Учет товаров на складе
- ✅ Движения товаров (приход/расход)
- ✅ Минимальные остатки и критические запасы
- ✅ Привязка расхода к заявкам
- ✅ История движений
- ✅ Статистика по категориям
- ✅ Фильтрация по критическим остаткам
- ✅ Поиск по SKU, названию, местоположению

#### Структура данных:
```typescript
interface InventoryItem {
  id: string;
  sku: string;              // Артикул товара
  name: string;             // Название
  category: InventoryCategory;
  description: string;
  quantity: number;         // Текущее количество
  minQuantity: number;      // Минимальный остаток
  unit: InventoryUnit;      // Единица измерения
  location: string;         // Местоположение на складе
  supplier?: string;        // Поставщик
  price?: number;           // Цена за единицу
  createdAt: string;
  updatedAt: string;
}

interface InventoryMovement {
  id: string;
  itemId: string;
  item: InventoryItem;
  type: 'in' | 'out';      // Приход или расход
  quantity: number;        // Количество
  reason: string;          // Причина движения
  ticketId?: string;       // Связь с заявкой
  documentId?: string;     // Связь с документом
  createdAt: string;
  author: User;
}
```

#### Категории товаров:
- **Запчасти** (spare_parts): Комплектующие для ремонта
  - Жесткие диски, оперативная память, видеокарты
  - Блоки питания, кулеры, корпусные детали
  
- **Расходники** (consumables): Расходные материалы
  - Картриджи для принтеров (HP 85A, Canon 728)
  - Бумага A4, кабели, переходники
  - Батарейки, диски, флешки
  
- **Оборудование** (equipment): Готовое оборудование
  - Компьютеры, мониторы, принтеры
  - Роутеры, коммутаторы
  
- **Инструменты** (tools): Инструменты для работы
  - Отвертки, пассатижи, кабель-тестеры
  - Паяльники, мультиметры
  
- **Другое** (other): Прочие товары

#### Единицы измерения:
- **шт** (pcs): Штуки
- **кг** (kg): Килограммы
- **л** (l): Литры
- **м** (m): Метры
- **кор** (box): Коробки

#### Workflow работы со складом:
```
1. Приход товара:
   - Добавить товар в систему (если новый)
   - Оформить движение "Приход" с указанием количества
   - Остаток автоматически увеличивается

2. Расход товара:
   - Найти товар на складе
   - Оформить движение "Расход" с указанием:
     * Количество
     * Причина (например: "Замена в каб. 205")
     * Привязка к заявке (опционально)
   - Остаток автоматически уменьшается

3. Контроль критических остатков:
   - Система показывает товары, где quantity <= minQuantity
   - Красная индикация в списке
   - Фильтр "Критические остатки"
```

#### Статистика:
- Общее количество позиций
- Товары с критическими остатками
- Общая стоимость товаров на складе
- Распределение по категориям

## 🔐 Система прав доступа (RBAC)

### Концепция:
Система построена на Role-Based Access Control (RBAC), где каждый пользователь имеет роль, а роль определяет доступные модули и действия.

### Уровни доступа:
- **View (Просмотр)**: Может просматривать данные
- **Create (Создание)**: Может создавать новые записи
- **Edit (Редактирование)**: Может изменять существующие записи
- **Delete (Удаление)**: Может удалять записи

### Матрица прав по ролям:

| Модуль | Admin | Technician | User | Viewer |
|--------|-------|------------|------|--------|
| База знаний | CRUD | CRUD | R | R |
| Заявки | CRUD | CRUD | CR | R |
| Документы | CRUD | R | R | R |
| Склад | CRUD | CRUD | - | R |
| Управление | CRUD | - | - | - |
| Профиль | CRUD | CRUD | CRUD | CRUD |

**Обозначения:**
- C = Create (Создание)
- R = Read (Просмотр)
- U = Update (Редактирование)
- D = Delete (Удаление)
- CRUD = Полный доступ
- - = Нет доступа

### Protected Routes:
Некоторые маршруты защищены на уровне роутера:
```typescript
// /tickets/:id/edit - требует право "edit" на модуль "tickets"
<ProtectedRoute moduleId="tickets" action="edit">
  <EditTicketPage />
</ProtectedRoute>

// /admin - требует право "view" на модуль "admin"
<ProtectedRoute moduleId="admin" action="view">
  <AdminPage />
</ProtectedRoute>
```

## 🔄 Workflow системы

### Типичный сценарий работы:

1. **Пользователь обнаруживает проблему:**
   - Проверяет базу знаний → находит решение самостоятельно
   - ИЛИ
   - Не находит решение → создает заявку

2. **Создание заявки:**
   - Указывает название и описание проблемы
   - Выбирает категорию (Оборудование, ПО, Сеть, Принтер)
   - Указывает приоритет
   - Заявка создается со статусом "Новая"

3. **Обработка заявки администратором/техником:**
   - Просматривает новые заявки
   - Назначает исполнителя (если есть несколько техников)
   - Переводит в статус "В работе"

4. **Работа над заявкой техником:**
   - Изучает проблему
   - Добавляет комментарии с описанием действий
   - При необходимости:
     - Проверяет склад на наличие запчастей
     - Заказывает недостающее
     - Переводит в статус "Ожидание"
   - Решает проблему
   - Оформляет расход со склада (если использовались запчасти)
   - Переводит заявку в статус "Решена"

5. **Документирование (опционально):**
   - Создает документ "Ремонт" с описанием работ
   - Указывает использованные запчасти
   - Прикрепляет фото/файлы

6. **Обновление базы знаний (если проблема типовая):**
   - Создает новую инструкцию или обновляет существующую
   - Другие пользователи смогут решить проблему самостоятельно

## 📖 Примеры использования

### Сценарий 1: Сломался принтер
```
1. Пользователь:
   - Открывает Базу знаний
   - Ищет "Принтер не печатает"
   - Следует пошаговой инструкции
   - Проблема решена ✅

2. Если не помогло:
   - Создает заявку "Принтер HP в каб. 205 не печатает"
   - Категория: Принтер, Приоритет: Средний
   - Заявка #1015 создана
```

### Сценарий 2: Замена картриджа
```
1. Техник получает заявку #1015
2. Проверяет склад → картридж HP 85A есть (3 шт)
3. Идет на место, меняет картридж
4. Оформляет расход:
   - Товар: Картридж HP 85A
   - Количество: 1 шт
   - Причина: "Замена в каб. 205"
   - Привязка к заявке #1015
5. Остаток автоматически: 3 → 2 шт
6. Закрывает заявку со статусом "Решена"
```

### Сценарий 3: Контроль критических остатков
```
1. Администратор открывает Склад
2. Включает фильтр "Критические остатки"
3. Видит: Картридж HP 85A (2 шт, минимум 5 шт)
4. Делает заказ поставщику
5. Приход товара:
   - Оформляет движение "Приход"
   - Количество: 10 шт
   - Причина: "Закупка, заказ #567"
6. Остаток: 2 → 12 шт ✅
```
